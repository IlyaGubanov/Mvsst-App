# Интерфейс (React + Vite)

## Как устроены файлы

```
client/
├─ index.html             страница-оболочка (шрифт, иконка)
├─ vite.config.js         при разработке пересылает /api на сервер localhost:3000
├─ public/                файлы «как есть»: favicon.svg, theme-init.js (тема до отрисовки)
└─ src/
   ├─ main.jsx            запуск, подключение стилей
   ├─ App.jsx             провайдеры и таблица адресов (маршрутов)
   ├─ api/                client.js — все запросы к серверу; overview.js — «Сводка»
   ├─ auth/               вход, смена пароля, «охранник» страниц, «кто я»
   ├─ theme/              светлая / тёмная тема
   ├─ layout/             верхняя панель с вкладками, меню пользователя
   ├─ components/         общие кирпичики: поле пароля, загрузка/ошибка, иконки
   ├─ pages/overview/     «Сводка»: итоги, карточки направлений, отставание, деньги, замечания
   ├─ pages/mkd/          Капремонт МКД: реестр адресов, карточка адреса, ввод за период
   │                      (itemForm.js — правила формы ввода: ошибки и предупреждения)
   ├─ pages/networks/     Сети: реестр по разделам, карточка с динамикой, ввод за период (netForm.js — правила)
   ├─ pages/schools/      Школы: обзор с вкладками, карточка школы, ежедневный ввод (schoolForm.js — правила)
   ├─ pages/              заглушка благоустройства (шаг 6 продолжается), «не найдено»
   ├─ directions.js       названия и цвета направлений
   ├─ utils/format.js     числа, деньги, проценты, даты по-русски
   └─ styles/             tokens.css (цвета, темы), base, shell, auth, overview
```

## Запуск при разработке

Нужны два окна терминала: сервер и интерфейс.

```bash
cd server
npm run dev
```

```bash
cd client
npm install
npm run dev
```

Откройте http://localhost:5173. Правки в коде видны сразу, без перезагрузки страницы.

## Сборка для рабочего сервера

```bash
npm run build
```

Готовые файлы — в `client/dist`. Их отдаёт Nginx (docs/03-deployment.md, C8) или сам сервер Node.js
при `SERVE_CLIENT=true` в `server/.env` (вариант для Windows Server без Nginx).

## Как это работает

- **Вход** — сеанс хранится на сервере, браузер получает только защищённую cookie. Пароль в браузере не сохраняется.
- **Временный пароль** — пока его не сменить, любая страница перенаправляет на «Придумайте свой пароль».
- **Роли** — вкладки и карточки строятся из направлений, которые сервер открыл пользователю (`/api/auth/me`).
  Кнопки ввода видны только тем, кто вносит данные. Окончательно права проверяет сервер.
- **Тема** — по умолчанию как в системе; кнопка в шапке переключает и запоминает выбор в браузере.
- **Срез на дату** — выбор даты в «Сводке» меняет адрес (`/?date=2026-10-15`), такой ссылкой можно поделиться.
- **Адаптивность** — до 620 px — телефон, до 1100 px — вкладки на второй строке, шире — всё в одну строку.

## Капремонт МКД

| Адрес | Экран |
|---|---|
| `/mkd[?period=]` | реестр адресов: итоги, фильтры (лот, риск, поиск, «только мои»), сортировка; на телефоне — карточки |
| `/mkd/:id[?period=]` | карточка адреса: сведения, итоги, позиции, история каждой позиции по периодам |
| `/mkd/input[?object=]` | ввод за период: мои адреса, статус / готовность / КС-2 / оплачено / примечание по позициям |

## Сети, коллекторы, водные объекты

| Адрес | Экран |
|---|---|
| `/networks[?period=]` | реестр: итоги, карточки 5 разделов (клик — фильтр), статусы, поиск, «только мои», сортировка |
| `/networks/:id[?period=]` | карточка: сроки, подрядчики, документы, объёмы (проект/факт), график и таблица динамики, договоры |
| `/networks/input[?object=]` | ввод за период: факт по линиям, закрыто КС, рабочие, техника; выполнение пересчитывается при вводе |

Общие компоненты: `components/Period.jsx` (полоса готовности, выбор периода), `components/DynamicsChart.jsx`
(график «факт против плана» на SVG, без внешних библиотек). Значения, подставленные при переносе из Excel,
помечены меткой «пример».

## Капремонт школ

| Адрес | Экран |
|---|---|
| `/schools[?tab=&date=]` | вкладки: **Обзор** (итоги, карточки школ, группы работ × школы, S-кривая), **Закупки** (оплата → поставка → монтаж, просрочки), **Испытания** (системы × школы), **Проект и МГЭ** |
| `/schools/:id[?date=]` | карточка школы: сведения, итоги, группы работ, виды работ с историей ввода, S-кривая, люди по дням, закупки, испытания, экспертиза |
| `/schools/input[?object=&date=]` | ввод за день: выполнение видов работ (процентом или объёмом) и люди/техника на здании и благоустройстве |

У школ нет отчётных периодов — вместо них **дата** (не позже сегодня). Если у работы есть проектный объём,
вводится факт объёмом, а процент считается сам. Ресурсы за день можно скопировать кнопкой «Те же, что за …».
При вводе задним числом приложение предупреждает: более поздние записи не меняются, запись идёт в историю.
Графики: `components/DynamicsChart.jsx` (S-кривая: план по неделям, факт — точками в дни ввода, отметка «сегодня»)
и `components/StackedBars.jsx` (столбики «здание + благоустройство» по дням).

## Общее для экранов ввода

Экран ввода сохраняет только изменённые позиции, подсвечивает их и показывает «было». Ошибки
(оплачено больше КС-2 и т.п.) не дают сохранить, предупреждения (уменьшилась готовность, КС-2 больше
договора) — только подсказывают. Уходя с несохранёнными изменениями, приложение переспросит.
